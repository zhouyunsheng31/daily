第一部分：App 的 HTML 渲染机制（关键背景）
================================================================================

文件: app/src/main/java/com/livingdashboard/ui/widget/HtmlCanvasWidget.kt
行: 177-187

App 的渲染逻辑是把 AI 生成的 HTML 直接嵌入 <body> 标签内：

    val wrappedHtml = """
        <!DOCTYPE html>
        <html>
        <head>
            <meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no">
            <style>html,body{margin:0;padding:0;width:100%;height:100%;overflow:hidden;box-sizing:border-box;}*{box-sizing:border-box;}</style>
        </head>
        <body>${html}</body>
        </html>
    """.trimIndent()
    loadDataWithBaseURL("about:blank", wrappedHtml, "text/html", "UTF-8", null)

★★★ 核心问题 #1：嵌套 HTML 文档 ★★★

当 AI 生成的 HTML 是完整文档（包含 <!DOCTYPE html><html><head><body>）时，
app 把它包裹在 <body>${html}</body> 里，会产生如下嵌套结构：

    <!DOCTYPE html>
    <html>
    <head>
        <meta name="viewport" ...>
        <style>html,body{...}</style>           ← app 的 CSS 重置
    </head>
    <body>
    <!DOCTYPE html>                              ← 被浏览器忽略
    <html>                                       ← 被忽略（已在 html 内）
    <head>                                       ← 被忽略（head 已关闭）
    <style>...</style>                           ← 作为 body 内 style 处理
    </head>
    <body>                                       ← 被忽略（已在 body 内）
        ... 实际内容 ...
    </body>
    </html>
    </body>
    </html>

虽然 HTML5 解析器能"修复"这种结构，但会导致：
  - CSS 优先级混乱（app 的 reset CSS 和 AI 的 CSS 冲突时行为不可预测）
  - <script> 执行时机问题（DOM 树可能和预期不同）
  - 某些 WebView 版本的解析器行为不一致

★★★ 核心问题 #2：JS 错误被静默吞掉 ★★★

文件: HtmlCanvasWidget.kt 行 174
    webChromeClient = WebChromeClient()

App 使用默认的 WebChromeClient，没有覆盖 onConsoleMessage()。
这意味着所有 JS 错误（TypeError、ReferenceError 等）和 console.log()
都不会出现在 logcat 中，无法从外部诊断 JS 执行情况。

-------- 白屏原因分析 --------

★★ 原因 A：100vh 在 WebView 中行为异常（影响组件 #2 和 #3）★★

组件 #2 和 #3 的 CSS:
    body {
        display: flex;
        justify-content: center;
        align-items: center;
        height: 100vh;          ← 问题在这里
        overflow: hidden;
    }

在 Android WebView + loadDataWithBaseURL 场景中，100vh 的行为和桌面浏览器不同：
  - vh 单位引用的是 layout viewport 高度
  - 虽然 app 设置了 viewport meta (width=device-width)，但 height 可能不受此控制
  - WebView 的 layout viewport 高度可能在初始加载时为 0 或一个很大的默认值
  - 如果 100vh = 0，body 高度为 0，flex 居中的内容不可见
  - 如果 100vh ≠ WebView 实际高度，内容可能被定位到可见区域外

app 的 CSS 重置用的是 height:100%（百分比），这是相对于父元素的，更可靠。
但 AI 生成的 CSS 用 height:100vh 覆盖了它，导致冲突。

★★ 原因 B：嵌套 HTML 文档导致 CSS 解析异常（影响组件 #2 和 #3）★★

组件 #2 和 #3 是完整 HTML 文档（<!DOCTYPE html><html><head><style>...）。
被 app 包裹后形成嵌套结构（见核心问题 #1）。

在嵌套结构中，AI 的 <style> 被放在 body 内（而非 head），虽然 HTML5 允许
body 内的 <style>，但：
  - CSS 层叠优先级可能和预期不同
  - 某些 CSS 属性可能在 body 上下文中行为不同
  - app 的 reset CSS（height:100%）和 AI 的 CSS（height:100vh）冲突时，
    由于都在 body 内，优先级取决于声明顺序，行为不可预测

★★ 原因 C：-webkit-text-fill-color: transparent 兼容性（影响组件 #2）★★

组件 #2 的 CSS:
    .time {
        font-size: 64px;
        background: linear-gradient(135deg, #f093fb, #f5576c, #4facfe);
        -webkit-background-clip: text;
        -webkit-text-fill-color: transparent;    ← 让文字变透明
        background-clip: text;
    }

这段 CSS 的意图是用渐变背景作为文字颜色。但如果 WebView 不支持
background-clip: text，文字会变成完全透明（不可见）。

在 Android 15 (API 35) 的 WebView 中，-webkit-background-clip: text
通常是支持的，但在某些 OEM 定制 ROM 上可能有问题。

如果文字透明 + body 背景未渲染（100vh=0 导致 body 高度为 0），
整个组件就显示为 WebView 的白色背景 → "完全白屏"。

★★ 原因 D：HTML 结构错误（影响组件 #3）★★

组件 #3 的 HTML 有一个多余的 </div> 标签：

    <div class="clock-widget">
      <div class="label">⏱ Digital Clock</div>
      <div class="digits">...</div>
      <div class="bottom">...</div>
    </div>                         ← clock-widget 的闭合标签
    <script>...</script>
    </div>                         ← ★多余的 </div>！无对应的 <div>

这会导致 HTML 解析器修复 DOM 树，后续内容（包括 </body></html>）
可能被放在意想不到的位置，影响渲染。

★★ 原因 E：JS 执行时机（影响所有组件）★★

所有时钟组件的 JS 都在 <script> 标签内同步执行（无 defer/async）。

组件 #1 的 JS:
    (function() {
      const hourHand = document.getElementById('hour');
      ...
      hourHand.style.transform = `translateX(-50%) rotate(${hourDeg}deg)`;
      ...
    })();

如果 DOM 元素未就绪（getElementById 返回 null），
hourHand.style.transform 会抛出 TypeError，脚本中断。
但由于核心问题 #2（JS 错误被吞掉），这个错误不会被记录。

不过组件 #1 的 <script> 在 <div> 之后，DOM 应该已解析前面的元素，
所以这个原因可能性较低。

-------- 白屏结论 --------

最可能的原因组合：
  1. height:100vh 在 WebView 中不等于 WebView 实际高度 → body 高度异常
  2. 嵌套 HTML 文档导致 CSS 解析和层叠异常
  3. -webkit-text-fill-color:transparent 让文字不可见（组件 #2）
  4. app 的 WebChromeClient 没有捕获 JS 错误，无法诊断

组件 #1（时钟，HTML 片段）最可能正常显示（无嵌套问题，用 height:100%）。
组件 #2（🕒 时钟）最可能白屏（100vh + 透明文字 + 嵌套）。
组件 #3（🕰️ Clock）可能白屏（100vh + 多余 </div> + 嵌套）。

第三部分：下雨动画底部 1/3 黑色分析
================================================================================

组件信息:
  id: e4455e09-8d78-4fb3-8214-a0193c40a438
  title: 🌧️ 雨夜动画
  尺寸: 400x350 (wxh)
  HTML 类型: 完整文档（有嵌套问题）

-------- 底部黑色原因分析 --------

★★ 原因 A：canvas.clientHeight 在脚本执行时返回 0 或部分值（最可能）★★

HTML 中的关键代码:

    <canvas id="rainCanvas"></canvas>
    <script>
    const canvas = document.getElementById('rainCanvas');
    const ctx = canvas.getContext('2d');

    let W, H;

    function resize() {
      W = canvas.width = canvas.clientWidth;      ← 设置 canvas 内部分辨率宽度
      H = canvas.height = canvas.clientHeight;    ← 设置 canvas 内部分辨率高度
    }
    resize();                                       ← ★立即执行！
    window.addEventListener('resize', resize);     ← 监听窗口大小变化
    ...
    function draw() {
      ctx.fillStyle = 'rgba(10, 10, 26, 0.3)';
      ctx.fillRect(0, 0, W, H);                    ← 用 W, H 填充背景
      ...
      requestAnimationFrame(draw);
    }
    draw();

问题分析:

1. <script> 在 HTML 解析到该标签时同步执行
2. 此时 canvas 元素已在 DOM 中（在 script 之前），但 CSS 布局可能未完成
3. canvas.clientWidth 可能返回正确值（宽度布局通常先完成）
4. canvas.clientHeight 可能返回 0 或部分值（高度布局可能未完成）

   场景 1: clientHeight = 0
   - canvas 内部分辨率: 400x0
   - H = 0
   - fillRect(0, 0, 400, 0) → 什么都不画
   - 整个 canvas 透明 → 显示 body 黑色背景 (#0a0a1a)
   - 症状: 整个画面黑色（不是"底部1/3黑色"）

   场景 2: clientHeight = 部分值（如 233，约为 350 的 2/3）
   - canvas 内部分辨率: 400x233
   - H = 233
   - fillRect(0, 0, 400, 233) → 填充 400x233 区域
   - canvas CSS 显示尺寸: 400x350 (height:100%)
   - 如果浏览器按标准行为缩放: 400x233 内容拉伸到 400x350 → 无黑色区域
   - 如果 WebView 不缩放（某些版本的行为）: canvas 只显示 400x233，底部 117px 显示 body 背景
   - 症状: 底部 1/3 黑色 ★符合用户描述★

   场景 3: 嵌套 HTML 导致 body 高度计算异常
   - AI 的完整 HTML 文档被 app 包裹，形成嵌套结构
   - 嵌套可能导致 body height:100% 的解析和预期不同
   - body 高度可能只占 WebView 的 2/3
   - canvas height:100% = body 的 100% = WebView 的 2/3
   - 底部 1/3 没有 canvas 覆盖，显示 WebView 白色背景
   - 但用户看到的是"黑色"不是"白色"...

   ★最可能的是场景 2★：
   canvas.clientHeight 在脚本执行时返回部分值（约 233px），
   canvas 内部分辨率被设为 400x233，
   但 CSS height:100% 让 canvas 显示为 400x350。
   某些 WebView 版本不按标准缩放 canvas 内容，
   导致 canvas 只在上部 233px 渲染，底部 117px 空白，显示 body 的 #0a0a1a 黑色背景。

★★ 原因 B：window.resize 事件永不触发 ★★

resize() 只在两种情况被调用：
1. 脚本执行时（立即调用一次）
2. window.resize 事件触发时

在 Android WebView 中：
  - window.resize 事件通常只在设备旋转时触发
  - WebView 的 layout 变化（如 Compose 布局更新）不触发 window.resize
  - 因此如果初始 resize() 获取了错误的 canvas 尺寸，永远不会被纠正

这意味着 canvas 的内部分辨率永远停留在初始值（可能是 0 或部分值），
即使后来 WebView 完成了正确的布局，canvas 也不会重新调整。

★★ 原因 C：嵌套 HTML 文档影响布局 ★★

雨夜动画是完整 HTML 文档（<!DOCTYPE html><html><head><body>），
被 app 包裹后形成嵌套结构。

嵌套结构可能导致：
  - body 的 height:100% 解析时机延迟
  - canvas 的 height:100% 在 body 高度确定前就计算了
  - 布局分阶段完成，脚本执行时只完成了部分布局

-------- 下雨动画结论 --------

根本原因：canvas 的 resize() 在脚本执行时调用，
此时 canvas.clientHeight 可能返回 0 或部分值（因为 CSS 布局未完成或嵌套 HTML 导致布局延迟）。
window.resize 事件永不触发，canvas 尺寸永远不会被纠正。

"底部 1/3 黑色"最可能的解释：
  canvas.clientHeight 返回了约 2/3 的正确值（约 233px 而非 350px），
  canvas 内部分辨率被设为 400x233，
  Canvas 内容只在上部 233px 区域渲染，
  底部约 117px（350-233）显示 body 背景色 #0a0a1a（接近黑色）。

第四部分：修复建议（仅供参考，未修改任何代码）
================================================================================

1. 【App 层面】区分 HTML 片段和完整文档
   - 如果 AI 生成的 HTML 以 <!DOCTYPE 或 <html 开头，不要再用 <body>${html}</body> 包裹
   - 直接使用原始 HTML（已包含完整的 html/head/body 结构）

2. 【App 层面】在 WebView 中注入 DOMContentLoaded 回调
   - 在 <head> 注入一段 JS，在 DOMContentLoaded 时调用 window.dispatchEvent(new Event('resize'))
   - 确保 canvas 的 resize() 能在布局完成后被重新调用

3. 【App 层面】覆盖 WebChromeClient.onConsoleMessage
   - 捕获 JS 错误和 console 输出，输出到 logcat
   - 便于诊断 WebView 渲染问题

4. 【AI Prompt 层面】
   - 要求 AI 生成 HTML 片段（不含 <!DOCTYPE>/<html>/<head>/<body>），而非完整文档
   - 禁止使用 100vh，改用 height:100%
   - 禁止使用 -webkit-text-fill-color:transparent（或提供 fallback）
   - canvas 的 resize() 应在 DOMContentLoaded 或 requestAnimationFrame 中调用
   - 不要在 canvas 后面留下多余的 </div>

5. 【AI Prompt 层面 - canvas 特定】
   - canvas 尺寸初始化应在 DOMContentLoaded 后
   - 应监听 ResizeObserver（而非 window.resize）获取容器尺寸变化
   - 示例:
     if (document.readyState === 'loading') {
       document.addEventListener('DOMContentLoaded', resize);
     } else {
       resize();
     }
     // 或更健壮:
     requestAnimationFrame(() => { resize(); draw(); });
