# Daily webOS 移动端原型设计 Brief

> 本文是三个方向的共同输入。三版只改变视觉语言和信息结构，不改变产品事实，便于横向比较。

## Assumptions

1. 产品暂用 `Daily` 名称；`webOS` 只作形态描述，不作为正式品牌。
2. 目标用户是希望用自然语言快速获得个人工具、同时又重视控制权和数据边界的移动端用户。
3. 解锁/登录后的默认页是 AI 助手，不是传统图标桌面；桌面是相邻系统页，可通过按钮或后续手势进入。
4. AI 最重要的演示任务是“生成旅行清单 App”，因为它能同时展示对话、构建、权限、安装、运行和再修改。
5. 首版 App 是静态 HTML 包，在受控 iframe 中运行。原型只模拟体验，不实际运行 iframe、ASR、TTS 或后端 Agent。
6. 语音是关键能力，但浏览器后台唤醒不属于首版承诺；原型中的录音波形只是交互状态演示。
7. 系统权限确认必须明显区别于普通 App 内容，且明确说明数据范围与授权时长。
8. 本轮重点是手机竖屏；桌面 Shell 不在本轮设计范围。
9. 没有正式 Logo、品牌色和字体规范，因此不伪造品牌资产；使用 `Daily` 文字标识和系统/本地字体。
10. 这是方向原型，不是生产代码；所有示例数据都服务于任务闭环，不表示真实账户数据。

## 核心用户故事

用户进入 Daily 后看到 AI 默认首页，输入或说：“给我做一个旅行清单 App，能按日期整理，离线也能用。”AI 显示自己将创建哪些文件、需要哪些权限以及预计结果。用户预览并允许 App 私有存储权限后，新 App 被安装到桌面。用户打开 App、勾选清单，再返回 AI 要求修改；系统创建新版本而不是覆盖旧版本。

## 必须覆盖的四个状态

1. **Assistant Home**：默认首页、上下文提示、文字/语音入口、桌面入口。
2. **Launcher**：分页桌面、App 图标或模块、Dock/系统入口、最近生成 App。
3. **Generate & Permission**：生成过程、预览、不可变版本、权限范围、确认动作。
4. **HTML App Runtime**：生成的旅行清单 App、宿主返回入口、版本标识、可交互清单。

## 设计约束

- 手机逻辑尺寸参考 iPhone 15 Pro：393 × 852；使用 Huashu `ios_frame.jsx` 的设备规格。
- 中文正文不小于 14px；说明文字不小于 12px；关键点击目标至少 44px。
- 中文使用「」引号，禁止合成斜体，数字使用 tabular nums。
- 不依赖外部图片或网络资源，双击 HTML 即可打开。
- 不用 Emoji 充当产品图标；图标使用内联线性 SVG 或纯 CSS 几何。
- 动画只用于状态变化和空间关系；支持 `prefers-reduced-motion`。
- 三版的导航、构图和内容分组必须有结构性差异，不能只换皮。
- 系统级授权层在视觉上必须高于 App，不能被 App 仿冒。

## 三个方向

### A — Quiet Intelligence / 安静智能

- 逻辑：AI 像一张会呼吸的个人工作台，而不是聊天软件。
- 结构：编辑式问候 + 少量上下文卡片 + 底部系统输入；桌面保持传统图标认知。
- 视觉：暖瓷白、墨色、克制钴蓝；细腻毛玻璃但不过量。
- 优点：学习成本低、可信、适合日常长期使用。
- 风险：需要通过文案和动效避免“只是一个漂亮聊天页”。

### B — Living Space / 流体空间

- 逻辑：语音和环境状态是主角，AI 以动态核心存在，App 是围绕它展开的个人空间。
- 结构：中心语音 Orb + 浮动上下文 + 玻璃 Dock；桌面采用大部件与图标混排。
- 视觉：深海墨色、珊瑚、薄荷和日光金；多层流体玻璃和受控光晕。
- 优点：个性化和“网页能比原生更自由”的卖点最强。
- 风险：性能和可读性必须有降级档位，不能把效果凌驾于任务。

### C — Agent Studio / Agent 工作台

- 逻辑：让用户看见 AI 正在做什么、改了什么、为什么需要权限。
- 结构：命令首页 + 活动流 + 模块化桌面；生成页突出文件、Diff、安全检查和版本。
- 视觉：碳黑、纸白、信号橙；规则线、模块网格、等宽元数据。
- 优点：Agent 能力、控制权和可审计性表达最清楚，适合高级用户。
- 风险：初次使用的情绪温度偏低，需要在 onboarding 中做渐进披露。

## 本轮判断标准

用户不是只选择“最好看的颜色”，而是判断：

1. 默认首页更应该像安静对话、语音生命体，还是 Agent 控制台？
2. 桌面更应该传统易懂、空间化，还是模块化？
3. 构建细节默认应隐藏、适度显示，还是充分透明？
4. 个性化应该成为首屏气质，还是保持在不打扰任务的位置？
5. 哪一版最像愿意每天打开的个人系统，而不是一次性 Demo？
