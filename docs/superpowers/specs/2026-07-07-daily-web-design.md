## 1. 项目定位

### 1.1 项目名称
- 项目叫 **Daily**，不叫 Living Dashboard
- 必须写进 `AGENT.md`，后续所有文档统一使用 Daily 这个名称

### 1.2 本质
- Daily = **画布 + AI Agent**
- 画布是前端交互页面，AI Agent 是核心能力
- 把 HTML 的所有优势发挥出来（动画、音乐、各方面能力）

### 1.3 产品形态
- **可部署的平台产品**：别人部署后直接能用，不用改源码
- 部署到服务器上，通过网页访问，适配电脑和手机体验
- 是部署在服务器上的服务，不是桌面端或移动端应用
- 用户部署 Daily 后，往自己服务器丢自己的服务，给服务做 HTML 前端放 Daily 上
- Daily 只是前端交互层，不管用户后端服务怎么跑

### 1.4 比赛策略
- 比赛交稿约 3 天，但**不做残缺版**，要做最好的效果
- 比赛只专心网页端，其他两端（桌面/移动）用户自己处理
- 整个项目都会提交上去

### 1.5 官方部署
- 官方（你们自己）部署最庞大的 Daily（三端：桌面/移动/网页）
- 当前的服务器就是主要服务器
- shadowshubs 容器要删掉，只留 Daily
- shadowshubs 做成 Daily 的内置官方社区面板（详见 §14）

## 2. 画布架构

### 2.1 架构选择
- **保持现状**（React 组件树 + iframe for HTML widget）+ **新增三层模型**
- React 组件树管状态（widget 位置/数据/交互）
- iframe 渲染 HTML（隔离好，AI 写的 HTML 不污染画布）
- React 最终也渲染成 HTML，本质上都是 HTML，不冲突

### 2.2 三层模型
画布分**三层**：

| 层 | 位置 | 特点 | 内容 |
|---|---|---|---|
| **背景层** | 最底 | 始终存在，不随相册缩放消失 | 图片/颜色/动画/基础组件（时钟等） |
| **组件层** | 中间 | 参与相册缩放，按大小决定缩放 | iframe widget + 自由 HTML 组件 |
| **弹出层** | 最上 | 临时弹出，用完消失 | 登录窗口、引导、广告等 |

### 2.3 画布是 HTML
- 画布本身是一个 HTML 文档
- 组件也是 HTML（iframe 里是 HTML，自由 HTML 组件也是 HTML）
- 三层都是 HTML
- 这样可以方便做动态效果

## 3. 组件类型

### 3.1 两类组件

#### iframe widget
- 矩形区域，有位置和大小（left/top/width/height）
- 可拖拽缩放
- 隔离好（独立浏览上下文，iframe）
- 内容只能在矩形内
- 适合：独立功能组件（如游戏、工具、计算器）

#### 自由 HTML 组件
- 任意形状，不限于矩形
- 自由移动（CSS 动画/JS 控制位置），可跨 widget 边界
- 可配置全局覆盖 or 局部
- 不可人为拖拽缩放（跟 iframe widget 区别）
- 无隔离（和画布共享 DOM）
- 适合：跨 widget 动画、装饰、全局特效
- AI 自动管理，但支持人操作和拖拽

### 3.2 背景层
- AI 可控画布属性
- AI 可以上传图片当背景
- AI 可以加特效（下雨等）
- AI 可以在背景某处放基础组件（时钟显示等）
- 背景上的东西始终存在，不随相册缩放消失

### 3.3 弹出层
- 全功能触发：
  - 进入时触发（第一次打开面板时）
  - 条件触发（未登录时、登录失效时、打开某东西时）
  - 定时触发（每过一段时间）
  - 手动触发（用户/AI 主动调用）
- 支持单次弹出 / 可重复弹出
- 多个弹出层可叠加
- 关闭条件：登录成功后自动关闭、用户点击关闭、定时关闭、AI 主动关闭

### 3.4 AI 生成 HTML 放置
- AI 生成 HTML 两种都支持（iframe widget + 自由 HTML 组件）
- AI 自己判断放哪
- 建议**优先自由 HTML 组件**（覆盖层）

## 6. 相册缩放

### 6.1 交互方式
- **滚轮自动吸附** + **工具栏按钮切换**（两者结合）
- 放大时组件保持原样
- 缩小时动态优化（档位吸附）

### 6.2 三档
| 档位 | 效果 |
|---|---|
| 最大 | 单个组件占满全屏 |
| 中 | 组件并列展示（自动网格布局） |
| 最小 | 只显示图标（卸载 iframe 省性能） |

### 6.3 档位触发值
- 用户可调（比如最大档位设为 zoom>2.0，最小档位设为 zoom<0.4）

### 6.4 缩放规则
- 缩放时**大的先缩小**（确保整体协调统一）
- 无论自由组件还是 iframe widget，都按大小决定怎么缩放
- 目标是保证整体美观协调

### 6.5 自由 HTML 组件与相册视图
- 分情况处理
- 按大小决定缩放
- 保证整体美观协调

### 6.6 背景层与相册视图
- 背景层不参与相册缩放
- 始终保持原样

### 6.7 性能方案
- **相册缩放 + 虚拟化**
- 最小档位卸载 iframe 只显图标（省内存）
- 中等档位虚拟化（只渲染视口内 widget）
- 保留 iframe 隔离性

## 9. 社区功能

### 9.1 社区模型
- 一个 Daily 部署 = 一个平台实例 = 一个社区
- 部署者 = 该实例的管理员
- 管理员可创建多个社区面板（按主题分区）
- 普通用户注册后，可创建个人面板，可加入社区面板

### 9.2 联邦式社区
- 每个社区独立用户系统
- 各社区独立注册登录
- 用户在 A 社区注册后，不能在 B 社区投稿，必须各自注册
- Daily 作为客户端聚合展示多个社区

### 9.3 社区发现
- **官方社区列表**（开发者提交申请，默认通过）
- 用户从官方列表选择添加，或手动输入地址

### 9.4 社区连接
- 创建社群面板时输入内容（社区地址/API），连接到外部社群
- 连接涉及用户管理、用户筛选
- 每个社区独立用户系统，Daily 聚合展示

### 9.5 社区功能实现
- **功能拆解 + 本地实现**（不嵌入 shadowshubs 前端）
- 把 shadowshubs 的能力拆成 widget，在 Daily 侧自己实现
- 用 AI Agent 辅助开发
- 不依赖 shadowshubs 前端

### 9.6 shadowshubs 角色
- shadowshubs 是"用 Daily 搭建的平台的范例"
- 别人觉得 Daily 交互方式有意思，用 Daily 来搭建自己的平台

现在我们分三个问题分别来讨论：

第一个问题：我们现在这个项目的现状是怎么样的？

第二个问题：我们最后需要一个怎样的东西来实现我的目标，来达成我阶段性的目标，为我后面的安排做下铺垫？

第三个问题：我接下来还要参加这个比赛，为了这个比赛，我该怎么去整这个作品？这个作品应该是怎样的一个东西？怎样才可以让它有更高的概率进复赛？

针对第一个问题，现在手上有两个项目，这两个项目其实都是以 HTML 为中心的：

1. AI 游戏平台：用 AI 做一个 HTML 游戏（H5 游戏），可以发布上去，也可以简单做一些连接把游戏整上去，是非常简单的东西。

2. Daily（日常管理）：专门用来服务于日常生活。核心是用户说话，AI 可以给生成 HTML 文件。目前一共做了三端：(a) 移动端：以浏览器为主，画布为次要。(b) 桌面端：浏览器和画布功能各占一半。(c) 网页端：刚起步，只做了一个画布功能。

HTML 本身非常有潜力，可以做游戏、做动画，也可以用来做很简单的前端和简单的静态托管，实用性非常广泛。

基于此，目前需要的东西主要包括：
1. AI 辅助生成 HTML
2. 良好的架构保证体验
3. 必须具备社区功能（哪怕简陋也必须做）
4. 开发顺序：(a) 先做网页端；(b) 网页端做完后再考虑做移动端；(c) 移动端做完后再考虑做桌面端

核心开发思路：
1. 先打造网页端：先做一个"什么都能做"的画布，围绕 HTML 实现不同的效果
2. 针对不同场景优化体验
3. 替代现有 H5 游戏平台
4. 满足后续学习需求

项目最核心的两个部分：
1. AI 本身的工具
2. 前端展现出来的效果与体验

为了比赛（交稿时间大概 10 号，算上今天可能只有 3 天左右）：
1. 交付目标：三端都能出一个勉强能用的版本
2. 作品功能需求：(a) 基础组件库，支持像 Skill 那样提取出不同的布局模板；(b) AI 适配修改；(c) 电脑部署

关于交互方式的调整：
- 页面布局问题：AI 对话作为组件存在，其他 HTML 组件怎么摆放
- HTML 组件开发策略：不重复造轮子，做基本组件，适配其他场景

交互方式三个思路：
- 思路一：AI 作为一个矩形的组件存在
- 思路二：像"街月星辰"或 360 的加速球，很小的圆形组件，始终摆在最顶上
- 思路三：像 Windows 任务栏，在下面做一个椭圆形的发送对话框，对话历史整成气泡摆在角落

Web OS 形态，分两种形态：AI 对话 / 应用直接占上全屏

相册缩放三档：
- 最大：一个 HTML 占满全屏
- 中等：每个照片有一定的空间去展示自己，并列放在一起
- 最小：只能看到图标

两种自由度：
1. 组件模式：缩到很小时可以设定让某些 HTML 组件保持原样，保持指定的大小
2. 拖动与缩放的轻松体验：鼠标滚轮放大缩小，随便一拖切换 HTML 组件

桌面切换：不要不同的面板，就只有一个面板（注：讨论后改为可多建）

社区功能：把 AI 游戏平台改造成像"画布"一样，内置组件+skill 辅助。可以做一个"包"，类似 skill，下载工具部署小东西。

不同用户单独分配一个面板（注：讨论后改为面板可多建）。

## 附录 B：讨论决策日志

以下是讨论过程中逐步确认的决策，按时间顺序记录：

1. 比赛只专心网页端，其他两端用户处理
2. UI 不分两种模式，现有自由画布缩放直接升级融入"相册缩放"效果
3. 社区功能 = test 目录里的 shadowshubs 项目
4. 两个面板：个人面板 + 社区面板
5. 新增多用户
6. 项目叫 Daily，不叫 Living Dashboard，写进 Agent.md
7. Daily 是可部署的平台产品，别人部署后直接用，不用改源码
8. 社群面板创建后弹出提示输入内容，连接其他社群
9. 上传有两种：本地开发组件上传部署 / 用户在基于 Daily 的平台上上传作品
10. 管理功能很少——撑死成员管理 + AI 配置管理
11. AI 工具全开放（PI 原本 7 个 + 现有 30 个）
12. 画布是 HTML，组件也是 HTML
13. 保持现状（React + iframe）+ 新增覆盖层
14. 覆盖层 = 画布属性 AI 可控
15. 面板可多建（个人可多建 + 社区可多建）
16. AI 工具设置页开关控制，默认关闭
17. 官方社区列表
18. 自建完整用户系统
19. 不要管时间，要做最好的效果
20. 去掉 8 个内置 widget，只保留 HTML 画布容器机制
21. AI 对话：浮球 + 底部任务栏切换，去掉矩形 AI 助手 widget
22. AI 生成 HTML 两种都支持，AI 自己判断
23. 社区面板创建时弹出登录窗口（覆盖层 HTML widget）
24. 各社区独立注册
25. 相册缩放 + 虚拟化
26. shadowshubs 做成 Daily 的内置官方社区面板
27. 部署者 = 管理员
28. 没有投稿/审核功能
29. 三层模型：背景层 + 组件层 + 弹出层
30. 背景层：AI 可控画布属性
31. 弹出层：全功能触发
32. 两类组件：iframe widget + 自由 HTML 组件
33. 组件导入：手动上传按钮 + API 接口上传
34. 开发者文档：专门文档 + AGENT.md 索引
35. 暂时不做：知识库、游戏开发 GUI、包概念、基础组件库
36. 档位触发值用户可调，大的先缩小保证协调
37. 背景层不随相册缩放消失
38. mini 级别 = AI 自己选择的精简 HTML 形态（不是简单缩放完整内容，本质是一个很小的 HTML）
39. icon 级别 = AI 自己画的 HTML 图标（不是固定方形，可以是圆形或任意形状）
40. AI 底部对话栏位置改为靠右侧（不放在中间），上方做类似微信聊天气泡的对话历史展示，更适合 AI 对话场景
41. 缩放控件入口：画布主页顶部不放缩放按钮，缩放只通过滚轮触发（三档吸附：normal→mini→icon）
