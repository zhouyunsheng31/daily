# M0-3 性能实测报告：端侧 pi（2026-08-15）

## 1. 测试环境

| 项 | 值 |
|---|---|
| 真机 | 魅族 Lucky 08（中端，骁龙 7 系同级） |
| 运行时 | proot-static v5.3.0（proot-me）+ ubuntu-base 24.04.3 arm64 rootfs |
| Node | v24.18.0（官方 arm64 tarball，/opt/node-v24.18.0-linux-arm64） |
| pi SDK | @earendil-works/pi-coding-agent 0.79.10 |
| 模型 | DeepSeek V4 Flash（BYOK：opencode.ai OpenAI 兼容端点，thinking=low） |
| 测试脚本 | `client/android/agent/harness/perf-test.js`（12 轮单会话 + 10 会话各 1 轮） |
| rootfs 位置 | `/data/local/tmp/daily-rootfs`（spike；正式落 `files/`） |

## 2. 结果

### 冷启动（proot 拉起 → harness ready → 可对话）

| 指标 | 实测 | 预算（11 §2） | 结论 |
|---|---|---|---|
| 冷启动到 ready | **2705ms** | ≤ 10s | ✅ 富余 3.7x |
| ping RTT | 3ms | — | 桥响应即时 |

> 对比：开发机 Operit proot 嵌套环境同测为 11.1s（嵌套 proot + 磁盘慢），真机原生 arm64 为 2.7s。**首启含 rootfs 下载另计（155MB，实测 4.3MB/s ≈ 36s，需引导进度 UI，M2-8 落地）**。

### 首 token 延迟（12 轮，thinking=low）

| 指标 | 实测 | 预算 | 结论 |
|---|---|---|---|
| 均值 | **~2.9s** | ≤ 5s | ✅ |
| 最小 / 最大 | 1.6s / 4.4s | — | 抖动来自端点网络往返，非本地瓶颈 |

### 进程 RSS（含 10 会话上下文）

| 指标 | 实测 | 预算 | 结论 |
|---|---|---|---|
| 首轮峰值 | 174MB | ≤ 300MB | ✅ |
| 稳定态（GC 后） | **140–142MB** | ≤ 300MB | ✅ 富余 2.1x |
| 12 轮上下文增长 | 平坦（174 → 140 后稳定） | — | 无泄漏迹象 |
| 10 会话后 | 142MB | — | ✅ |
| heapUsed | 43MB | — | 健康 |

## 3. 结论

**M0-3 达标**，三项红线（RSS ≤300MB / 首 token ≤5s / 冷启动 ≤10s）全部通过且富余充足。
数据已并入 `docs/android/11-performance.md` §2 预算表实测列。

## 4. 附带修复（本轮测试暴露）

- `process.memoryUsage()` 在 proot 下因 `/proc/self/statm` 虚拟化失败抛 ENOENT → main.js status 加 try-catch 防御 + 启动参数 `-b /proc:/proc`（绑定宿主 proc 后恢复正常，rss 数据可信）。
- perf-test.js stdout/stderr 共用行缓冲导致 JSON 行被日志打断 → 分离双缓冲。
