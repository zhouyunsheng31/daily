# 01 · 产品定位与用户旅程

> 本文回答：给谁用、解决什么、用户从第一次打开到深度使用的每一步长什么样、怎样的设计才算"像手机一样轻松使用"。

## 1. 定位

**「你的第二个桌面——更轻量，也更个性化。」**

- **不是**又一个聊天 App：AI 是系统的入口和主生产力，对话是为了"让系统变成你想要的样子"。
- **不是**要替换系统桌面（M1 不承诺 Launcher 模式）：它是一个应用内的完整桌面环境——图标、壁纸、桌宠、App、商店、文件、联机。
- **核心爽点**：说一句话，桌面就多一个会动的东西；再说一句，它就变成你想要的样子。一切可改、一切可回滚。

目标用户：愿意折腾个性化的年轻 Android 用户 + AI 重度用户。他们追求"本地可控"（数据可备份、能力可授权、版本可回滚），这正是原生端相对网页端的核心价值。

## 2. 体验三原则（所有设计决策的裁判标准）

1. **零门槛进得来**：打开 30 秒内能和 AI 说上话（游客自动发放，无注册墙）。登录只为同步/迁移/更多额度。
2. **看得见摸得着**：AI 做的每件事都有即时可见的反馈（桌面多了个 App、桌宠动了起来、主题变了）。"AI 在干活"的过程对用户透明（工具调用 chip、进度）。
3. **永远回得去**：任何 AI 改动都可撤销/回滚；任何授权都可收回。用户永远不怕"让 AI 试试"。

## 3. 用户旅程（J1–J7，UI 设计必须与之一一对应）

### J1 首次打开（Onboarding）——目标：60 秒内完成首次对话

```
启动页(≤1s) → 一句话欢迎语 + 「开始体验」 → 直接进入对话主页（游客身份已自动发放）
            → AI 主动打招呼并给出 3 个可点建议（"给我做个倒数日" / "桌面放个桌宠" / "看看能干什么"）
```
- **不**在首启堆权限弹窗。权限在**用到时**才引导（J2）。
- 首启只展示一个轻量公告卡（可"不再显示"），不得遮挡输入框。

### J2 能力引导（权限按需）——目标：用户理解"为什么给"

触发式引导，三档场景：
- **桌宠/悬浮图标**（需悬浮窗权限）：AI 答应做桌宠 → 系统弹出引导卡（一句话说明 + 去开启按钮 + 稍后再说）→ 回来自动继续任务。
- **截屏/看屏幕**（MediaProjection）：用到才弹。
- **增强模式**（Shizuku，Tier1）：仅在用户点了"增强模式"入口或任务明确需要时出现，用图文说明激活步骤（装 Shizuku → 无线调试启动 → 回来自动检测）。绝不强制。

### J3 日常对话 —— 目标：像微信一样顺手

- 输入框常驻底部；支持图片附件、长按语音输入预留位（M2 见 08-media-ai）。
- AI 回复流式渲染；思考过程可折叠；工具调用以 chip 展示（进行/成功/失败态）。
- 断网/断流自动恢复（服务端已支持 SSE resume，客户端实现重连）。
- 消息可长按：复制/引用/删除/回退重发（rebuild）。

### J4 AI 创建与修改 App —— 目标：魔法时刻

```
用户："给我做个记账 App" → AI 流式回复 + 工具 chip（建文件夹/写代码/生成图标）
→ 完成后对话内出现「打开」卡片 → 点击全屏打开 App（WebView 沙箱）
→ 桌面同步出现图标（实时刷新）
用户："把预算页改成深色" → AI 修改 → 新版本 → App 内提示"已更新，重启生效/热刷新"
```
- App 运行页手势：顶部下拉或右下角悬浮钮呼出「App 信息」（版本/权限/API/回滚/删除）。
- 历史版本列表 = 时间线，点旧版本一键回滚。

### J5 桌面个性化 —— 目标：第二个桌面立起来

- 桌面页：图标网格 + 自由摆放（长按拖拽）+ 壁纸 + 桌宠层。
- 长按图标：打开/信息/移除/固定到…（菜单必须单手可达）。
- 对 AI 说"让图标都漂浮起来"→ 桌面进入自由悬浮模式（物理动画，点击照常触发）——这是招牌体验，必须流畅且可一键复原。

### J6 联机与分享 —— 目标：作品能流动

- App 详情页「分享」→ 生成链接/二维码 → 对方（网页端或 Android 端）打开即安装。
- 联机 App（论坛/聊天室/对战）：「邀请」→ 生成房间链接 → 双方进入同一房间实时同步（06-realtime）。
- 商店：浏览/搜索/安装/评价（评价后置）；"AI 帮我找"入口：对话里说需求，AI 搜商店并推荐安装。

### J7 账号、备份与恢复 —— 目标：换机不怕

- 游客 → 邮箱验证码登录（自动迁移游客资产，现有 `/api/auth/email/*` 端族复用）。
- 设置页：余额/用量/套餐（爱发电/支付状态如实展示，不可伪造）。
- 备份：自动云备份状态（上次时间）+ 手动"立即备份" + "导出到本地文件" + 换机"从备份恢复"。恢复走版本指针，可再回滚（09-files-sync-backup）。

## 4. 可用性原则（"像手机一样轻松使用"的具体化，验收逐条过）

| 类别 | 要求 |
|---|---|
| 导航 | 底部 4 主Tab（对话/桌面/商店/我的），任何页面 2 步内回主页；Tab 切换不重载（状态保活） |
| 单手可达 | 主要操作区在屏幕下 2/3；弹层底部弹出；长按菜单不出现在顶部 |
| 手势 | 系统返回键/手势全页面可用；App 运行页右滑返回桌面；桌面长按出菜单，拖拽换位 |
| 反馈 | 所有异步操作有 loading/进度；失败用 Snackbar + 重试；AI 长任务有实时过程（busy_waiting/background_progress 已有协议） |
| 文字 | 最小 13sp；按钮文案动词开头（"创建""开启""恢复"），禁止技术黑话（不出现 "SSE""沙箱""broker"） |
| 空态 | 每个空列表都有插画 + 一句话 + 可点行动（如"让 AI 给你做一个"） |
| 错误 | 错误=人话 + 怎么办（"网络开了小差，点这里重试"），不裸抛 code |
| 一致性 | 同一类操作同一交互（所有删除都二次确认 + 可撤销 toast） |
| 无障碍 | 全部可点元素 ≥48dp；对比度 ≥ WCAG AA；ContentDescription 齐全 |
| 打断恢复 | 来电/切后台/锁屏后回来，对话任务继续（服务端后台任务已有支持），桌宠/悬浮层状态不丢 |

## 5. 明确不做（M1 范围外，防止蔓延）

- 系统 Launcher 替换（ROLE_HOME）、ASR/TTS 语音对话（仅留架构位，见 08）、Live2D/3D 桌宠渲染器、真 WebRTC P2P、本地大模型推理、桌面小组件(App Widget)、手表/TV 形态。
- 每一项的架构预留已在对应分篇写明；M1 开发中遇到"顺手就能做"的诱惑时，回来查本清单。
