# Daily webOS 首版功能清单

> 状态：Draft / 方向 A 已选定，等待 P0 范围确认  
> 更新日期：2026-07-31  
> 产品基线：移动端优先、AI-native、方向 A「安静智能」、纯文字交互

## 1. 已确认的首版决策

- 方向 A「安静智能」是首版默认且唯一主题；方向 B、C 仅保留为后续可选主题参考。
- 首版不做 ASR、TTS、麦克风输入、语音 Orb、唤醒词或后台录音。
- 用户无需登录即可进入系统；首次打开自动创建游客身份并发放固定免费额度。
- 登录只用于绑定邮箱、跨设备同步以及游客数据和余额权益迁移，不是使用门槛。
- 登录方式为邮箱验证码，不提供密码登录；首版先完成 UI、状态与接口抽象，真实发信 API 待提供。
- 支付页面进入 P0；真实支付 API 提供前只实现价格展示、支付入口、订单状态和 Provider 抽象，不模拟真实扣款成功。
- AI 模型和思考强度是两个独立控制项，均进入 P0。
- P0 只支持静态 HTML App；App 默认全屏运行，修改创建不可变新版本。
- 首版不设置产品锁屏，不做多任务卡片、公共商店、外部 URL App 或托管服务 App。

## 2. P0：首版必须完成

### P0.1 PWA Shell 与导航

- 可安装的移动端 PWA Shell，适配 safe-area、软键盘、触控和浏览器返回。
- 首次打开直接进入 AI 助手首页，无登录拦截页、无产品锁屏。
- 核心导航闭环：`AI 首页 → 系统桌面 → App → 返回桌面/AI`。
- App 默认全屏运行，由宿主栏提供返回、版本信息和“让 Daily 修改”。
- 离线时可启动 Shell、打开已缓存的内置壳与已安装静态 App；涉及云端 AI、登录和支付时明确提示需联网。
- 首屏恢复最近会话和最近打开 App，不做多任务卡片管理。

### P0.2 游客身份、余额与迁移

- 首次访问自动生成不可猜测的 `guestId` 和本地会话凭据，不要求填写资料。
- 为游客发放固定免费余额；具体数值、有效期和刷新策略通过配置决定。
- AI 首页和设置页始终可查看余额、预计消耗和最近用量。
- 生成前进行额度预估；余额不足时阻止付费调用，并引导绑定邮箱或前往充值。
- 游客可创建 App、保存私有数据并查看版本历史，受游客存储与余额上限约束。
- 邮箱绑定成功后，把游客身份、App、App 私有数据、版本、用量和未消耗权益原子迁移到账户。
- 迁移必须幂等；失败时保留游客数据，不得出现资产重复或丢失。
- 提供“清除本机游客数据”入口，并明确说明清除后的恢复限制。

### P0.3 邮箱验证码登录与绑定

- 入口文案以“绑定邮箱并同步”表达，不用“登录后才能继续”。
- 流程：输入邮箱 → 获取验证码 → 输入验证码 → 绑定/登录 → 迁移确认结果。
- 包含发送中、倒计时、验证码错误、过期、频率限制、邮箱已绑定、网络失败等状态。
- 验证码 API、SMTP/邮件服务通过 `EmailVerificationProvider` 抽象；真实供应商配置待提供。
- 原型和未接 API 的开发版本必须标记“服务待接入”，不能接受任意验证码并伪装成功。
- 会话支持安全退出；退出后可重新进入游客模式，但不得静默删除已同步账户资产。

### P0.4 余额、套餐与支付页面

- AI 首页显示当前身份、余额和快捷充值入口。
- 支付页展示可配置的充值包/套餐、金额、权益、有效期和适用范围。
- 下单前展示支付金额、预计到账、条款入口和当前账户归属；游客支付前应提示绑定邮箱以降低资产丢失风险。
- 提供 `PaymentProvider`、商品目录、订单创建、支付跳转/二维码、状态查询、Webhook 验签和权益发放的抽象边界。
- 业务层只识别内部 `productId` / `orderId` / entitlement，不直接判断某支付平台商品 ID。
- 真实 API 未接入时，按钮明确显示“支付服务待接入”或禁用；不得伪造扣款成功、到账或订单号。
- P0 需要设计成功、处理中、取消、失败、重复通知和超时状态，但真实成功态只由已验签的支付结果驱动。
- 支付和额度变更全部写入可审计账本，要求幂等处理。

### P0.5 AI 首页与文字对话

- 解锁/启动后的系统主页就是 AI 助手，不先展示图标桌面。
- 方向 A 视觉：暖瓷白、墨色、克制钴蓝、低噪声卡片和纯文字输入框。
- 支持流式文字回复、停止生成、重试、错误恢复和新建会话。
- 支持建议提示词、最近上下文、生成计划摘要和用量预估。
- 输入区不出现麦克风、声波、语音状态或 TTS 控件。
- AI 生成 App 前说明要创建什么、预计消耗和所需权限；用户确认后再安装。

### P0.6 模型选择

- 模型选择是独立控制项，显示模型名称、能力标签、价格倍率、上下文/速度提示和可用状态。
- 模型列表由服务端配置/Provider 能力返回，原型示例名不构成最终供应商承诺。
- 会话可选择模型；默认模型由平台配置，停用模型有安全回退。
- 每次请求和用量事件记录实际模型与 Provider，不只记录 UI 展示名。
- 模型切换不得隐式改变思考强度；若组合不支持，需明确解释并要求用户选择兼容项。

### P0.7 思考强度

- 与模型选择分离，提供四档：`快速`、`平衡`、`深度`、`极深`。
- 思考强度控制推理预算、延迟和费用预估，不代表切换模型。
- 各档位通过 Provider Adapter 映射到真实 API 参数；业务/UI 不直接硬编码供应商字段。
- 模型不支持某档位时，应禁用该档或降级并明确提示，不能静默映射。
- 默认使用“平衡”；每个会话记住选择，用户可在发送前调整。

### P0.8 AI 生成、预览与安装静态 HTML App

- 用户可用自然语言创建静态单 HTML/静态 ZIP App。
- 生成流程包含需求摘要、文件生成、Manifest 校验、安全检查、沙箱预览、权限确认、用量结算和安装。
- 首版 App 能力只开放 `app.storage.private`；不开放网络、用户文件、麦克风、剪贴板和宿主 DOM。
- iframe 使用 opaque origin sandbox，通过 MessageChannel 与受控 SDK 通信。
- 生成失败不得影响已安装版本；失败/取消任务按结算规则退回未消耗额度。
- 安装前清楚显示 App 名称、版本、来源、权限和私有数据边界。

### P0.9 App 修改、不可变版本与回滚

- App 内“让 Daily 修改”会携带当前 `appId`、`installId` 和源版本进入 AI 会话。
- 每次修改创建新的不可变 `AppVersion`，不覆盖旧 Artifact。
- 安装实例仅原子切换 `activeVersionId`，保留来源、差异和审计链。
- 新版本增加权限时必须重新授权。
- 提供版本列表、当前版本标识、更新预览、回滚和失败回退。
- 回滚只切换版本指针，不删除后续版本；App 私有数据迁移失败时保持旧版本可用。

### P0.10 系统桌面与默认内置应用

首版桌面固定提供以下四项；系统应用使用平台签名和固定系统标识，不伪装成普通第三方 App：

1. **Daily AI 助手**：系统主页和主要创建入口，不可卸载。
2. **系统桌面**：应用启动器与已安装 App 列表，不可卸载。
3. **文件管理器**：展示用户文件、App 数据概览和基础存储用量；P0 提供可打开的基础 UI 与受控占位，不向 HTML App 开放文件权限。
4. **系统设置**：账户与游客迁移、余额与支付、模型、思考强度、存储、隐私和系统信息，不可卸载。

同时满足：

- AI 新生成的 App 安装后出现在桌面，并有“新建”标识。
- 桌面 P0 采用传统图标网格；不做自由拖拽、Bento 布局、分页定制或小组件编辑。
- 不内置公共应用商店。原型中的“App 市集”从 P0 移除。
- 旧无限画布未来作为内置 Canvas App 迁入，但不作为新 Shell P0 阻断项。

### P0.11 文件管理器基础界面

- 展示“我的文件”“App 数据概览”和存储用量。
- 提供最近文件、空状态、存储分类和清理入口的基础 UI；真实云同步取决于后续存储接入。
- “导入 HTML/ZIP App”在 P0 仅显示规划入口或不可用说明，不执行解包和安装。
- P0 不提供给第三方 App 的任意文件读写授权，不暴露真实服务器路径。
- 删除文件和 App 前明确影响范围；关键数据先进入回收/可恢复状态。

### P0.12 系统设置

- **账户**：游客 ID 摘要、邮箱绑定、同步状态、退出、数据迁移说明。
- **余额与支付**：当前余额、免费额度、充值入口、订单记录占位、用量明细。
- **AI**：模型选择和思考强度两个独立区域，显示价格/延迟影响。
- **存储**：总用量、App 私有数据、版本占用和清理入口。
- **隐私与安全**：App 权限、会话、游客数据清除和审计入口。
- **系统**：PWA 版本、更新状态、离线缓存和诊断信息。

### P0.13 用量账本、额度阻断与接口抽象

- 统一记录 AI token/模型/推理档位、生成任务、存储和权益变更。
- 所有用量事件有幂等键，支持预授权/预估、实际结算、失败释放和人工调整审计。
- 余额不能只存在客户端；客户端缓存仅用于展示和离线提示。
- AI Provider、模型目录、思考强度映射、邮件验证码和支付都必须通过可替换接口接入。
- 未提供真实 API 前使用明确的 unavailable/mock-development 状态，不把演示数据写成真实交易或真实登录。

### P0.14 基础安全、隐私与可访问性

- 鉴权令牌、对象存储密钥和支付密钥不下发 iframe。
- 游客凭据使用安全存储策略并支持轮换；敏感接口有速率限制和滥用防护。
- 邮箱验证码不写入普通日志；支付回调必须验签、防重放。
- App 包做 CSP/资源限制、路径校验、大小限制和静态安全扫描。
- 44px 触控目标、读屏语义、对比度、减弱动效和中低端设备降级。
- 提供隐私说明、条款入口、数据删除/导出入口占位和错误诊断 ID。

## 3. P1：核心闭环稳定后补充

- 文件授权扩展到指定文件/目录、只读/写入/删除，并接 Permission Broker。
- 本地单 HTML/静态 ZIP 导入、包校验、沙箱预览与安装。
- 私有 App Library 的搜索、分组、导出、分享和跨设备完整同步。
- 最近任务卡片、App 挂起/恢复和更完整的后台生命周期。
- 更丰富的内置 App，例如 Canvas、笔记、相册；旧 Dashboard 能力逐步迁移。
- 受控主题包；方向 B、C 可作为可选主题实验，但不改变权限和版本安全边界。
- 通知、剪贴板、受控网络请求等新增 App Capability。
- 更细的账单、退款自助、优惠活动与订阅管理（取决于真实支付 Provider）。
- Passkey/WebAuthn、账户恢复和更多登录安全能力。
- App 开发者工具、Manifest 检查器、Diff 与高级审计视图。

## 4. 明确不进入首版

- ASR、TTS、语音输入、语音 Orb、唤醒词和后台录音。
- 公共应用商店、社区发布、审核、评分、自动更新和付费 App 分成。
- 外部 URL App、Node/Python 服务型 App、云容器编排和一键托管。
- 桌面端 Shell、自由拖拽桌面、Bento 桌面、产品锁屏和多任务卡片。
- 向第三方 HTML App 开放网络、麦克风、任意文件系统、剪贴板或宿主 DOM。
- 在真实 API 未提供前伪造邮箱验证码成功、真实支付成功或真实 AI 费用。

## 5. P0 验收主路径

```text
首次打开
→ 自动获得游客身份和免费余额
→ 在 AI 首页独立选择模型与思考强度
→ 描述 App 需求并查看预计消耗
→ 生成静态 HTML App
→ 查看预览与 app.storage.private 权限
→ 安装并全屏打开
→ 让 Daily 基于当前版本修改
→ 创建新版本并可回滚
→ 从桌面打开 AI / 桌面 / 文件 / 设置
→ 在设置中查看余额、绑定邮箱迁移游客资产
→ 进入支付页；未接真实 Provider 时明确显示服务待接入
```

P0 是否完成，以这条路径在游客身份下可跑通为首要标准；邮箱和支付的真实成功闭环在相应 Provider/API 提供后验收。
