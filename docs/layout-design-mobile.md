## 一、概述

### 1.1 产品定位

**形态**：浏览器 + 无限画布 + AI

**用途**：日常 AI 助手

Living Dashboard 是一款融合浏览器与无限画布的 AI 助手产品。它既是浏览器（上网工具），又是画布（个人数据管理），核心是贯穿两者的 AI 能力。产品包含桌面端（Electron + React + TypeScript）和移动端（Kotlin + Jetpack Compose + WebView），双端共享服务器数据，实现多端互通。

> 桌面端布局设计见 [layout-design-desktop.md](layout-design-desktop.md)

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **对称设计** | 浏览器主页与画布主页在布局上对称（pill 搜索框↔pill AI 输入框、Logo↔圆形图标、书签圆形网格↔收藏组件图标网格），降低学习成本 |
| **原生优先** | 桌面端用 Electron 原生渲染，移动端用 Kotlin + Compose 原生 UI，保证丝滑体验 |
| **轻量优先** | 移动端复用系统 WebView，包体 < 20MB；桌面端 tree-shaking 图标 |
| **多端互通** | 共享服务器数据库，面板/组件/AI 对话/书签/脚本/收藏组件跨端同步 |
| **透明优先** | 组件不使用实线边框，以半透明背景和毛玻璃效果区分层次，营造轻盈通透的视觉感受 |

## 二、移动端布局设计

### 2.1 整体框架布局（App Shell + BottomBar）

**状态**：已实现（M0-M1）

**功能描述**：移动端整体框架，由底部栏（BottomBar，圆形按钮风格）和导航图组成。所有页面都在 BottomBar 之上渲染。

**ASCII 线框图**：

```
┌─────────────────────────────────────┐
│          （系统状态栏）               │
│                                     │
│                                     │
│          页面内容区域                 │
│     （根据导航状态切换）              │
│                                     │
│                                     │
│                                     │
│                                     │
├─────────────────────────────────────┤
│  ◯  ◯  ◯  ◯  ◯                    │  ← ░BottomBar░ 毛玻璃（圆形按钮）
│  后退  前进  主页   标签页  更多     │
└─────────────────────────────────────┘
```

**组件层级**：

```
MainActivity
├── MainActivityContent
│   ├── NavHost（Compose Navigation）
│   │   ├── homeScreen（浏览器主页 / 画布主页）
│   │   ├── browserScreen（浏览器页）
│   │   ├── tabManagerScreen（标签管理）
│   │   ├── bookmarkScreen（书签管理）
│   │   ├── historyScreen（历史记录）
│   │   └── settingsScreen（设置）
│   └── MoreMenuSheet（更多菜单半屏面板）
└── BottomBar（5 个圆形按钮）
```

**交互行为**：

| 用户操作 | 系统响应 |
|---------|---------|
| 点击底部栏按钮 | 触发对应导航动作 |
| 上滑底部栏 | 切换到 AI 输入框模式 |
| 系统返回键 | 导航回退 |

**手势操作**：无特殊手势，底部栏按钮点击为主。

**与桌面端的对应关系**：对应桌面端 App Shell。移动端的底部栏整合了桌面端顶部栏（导航）+ 侧边栏（面板管理）+ 底部工具栏的部分功能。

**组件层级**：

```

├── LogoHeader（Logo + 品牌名）
```

| 用户操作 | 系统响应 |
|---------|---------|
| 搜索框输入 URL | 导航到该 URL |

| 点击书签圆形图标 | 导航到该网站 |
| 长按书签圆形图标 | 弹出菜单（编辑/删除） |
| 点击 Home | 切换到画布主页 |

**手势操作**：

| 手势 | 响应 |
|------|------|
| 长按书签圆形图标 | 弹出菜单（编辑/删除） |

**与桌面端的对应关系**：对应桌面端 BrowserHome。移动端仅图标模式，无预览模式。

**组件层级**：

```
AggregatePanelScreen
├── 上滑提示
├── 画布容器（类似 CanvasScreen，但只放收藏组件）
│   └── WidgetContainer × N（收藏组件的真实引用）
└── BottomBar（画布模式：◯◯◯◯◯）
```

**交互行为**：

| 用户操作 | 系统响应 |
|---------|---------|
| 上滑 | 回到画布主页 |
| 操作组件 | 修改同步到原面板（真实引用） |
| 双指缩放 | 缩放聚合面板 |

**手势操作**：

| 手势 | 响应 |
|------|------|
| 上滑 | 回到画布主页 |
| 双指缩放 | 缩放面板 |

**与桌面端的对应关系**：桌面端无聚合面板概念，收藏组件直接在画布主页预览。

## 三、双端对比矩阵

### 3.1 页面双端对应关系

| 功能域 | 桌面端页面 | 移动端页面 | 对应关系 |
|--------|-----------|-----------|---------|
| 整体框架 | App Shell（顶部栏+侧边栏+主区域） | App Shell（BottomBar+导航图） | 结构重组 |
| 浏览器主页 | BrowserHome | BrowserHomeScreen | 功能对等，桌面端有预览模式 |
| 画布主页 | CanvasHome | CanvasHomeScreen（规划中） | 功能对等，移动端有聚合面板入口 |
| 网页浏览 | WebTabFullscreen | BrowserScreen | 功能对等，地址栏位置不同 |
| 画布操作 | Workspace + UnifiedToolbar | CanvasScreen（规划中） | 功能对等，交互方式不同 |
| 标签管理 | TabBar（内嵌在顶部栏） | TabManagerScreen（独立页面） | 形态不同，功能对等 |
| 面板管理 | Sidebar（左侧常驻） | TabManagerScreen（统一管理） | 形态不同，功能对等 |
| 书签管理 | BrowserHome 内嵌 | BookmarkScreen（独立页面） | 形态不同，功能对等 |
| 历史记录 | 无独立页面 | HistoryScreen（独立页面） | 桌面端缺失 |
| 设置 | SettingsPanel（抽屉覆盖层） | SettingsScreen（独立页面） | 形态不同，功能对等 |
| AI 快速输入 | GlobalQuickInput（左 Alt） | 底部栏 AI 输入框模式（上滑） | 触发方式不同 |
| 组件搜索 | WidgetSearch（Ctrl+F） | 无 | 移动端缺失 |
| 小地图 | Minimap（画布右下角） | 无 | 移动端缺失 |
| 更多菜单 | 右键菜单 + SettingsPanel | MoreMenuSheet（半屏面板） | 形态不同 |
| WebOS 组件页 | 无（直接跳转画布位置） | WebOSWidgetScreen（规划中） | 移动端独有 |
| 聚合面板 | 无 | AggregatePanelScreen（规划中） | 移动端独有 |

### 4.2 Home 键行为规则（移动端精确规则）

| 当前状态 | 点 Home 后 | 说明 |
|---------|-----------|------|
| 看网页时（BrowserScreen） | 回浏览器主页 | 不跳画布主页 |
| 画布模式时（CanvasScreen） | 回画布主页 | 不跳浏览器主页 |
| 在浏览器主页时 | 切换到画布主页 | 主页间切换 |
| 在画布主页时 | 切换到浏览器主页 | 主页间切换 |

**核心规则**：Home 键**先回当前模式的主页**，再在主页间切换。不会跨模式跳跃。

**首次启动**：让用户选择默认主页（浏览器 or 画布），之后记住选择。

### 4.3 主页切换逻辑（移动端）

| Home 键（画布模式时） | 画布主页 |
| Home 键（浏览器主页时） | 画布主页 |
| Home 键（画布主页时） | 浏览器主页 |

## 六、响应式策略

### 6.1 移动端横竖屏适配

**竖屏（默认）**：

| 元素 | 行为 |
|------|------|
| BottomBar | 底部固定，5 按钮等宽 |
| 地址栏 | 顶部固定，URL 输入框占满宽度 |
| 书签圆形图标网格 | 4 列 |
| 标签卡片 | 全宽卡片 |

**横屏**：

| 元素 | 行为 |
|------|------|
| BottomBar | 底部固定，按钮间距增大 |
| 地址栏 | 顶部固定，URL 输入框更宽 |
| 书签圆形图标网格 | 6-8 列 |
| 标签卡片 | 2-3 列网格 |
| 画布 | 更宽的视口，组件排列更宽松 |

### 6.2 平板适配

当前未做平板专项适配。以下是规划方向（M7+）：

| 设备 | 屏幕宽度 | 适配策略 |
|------|---------|---------|
| 手机竖屏 | < 600dp | 当前布局 |
| 手机横屏 | 600dp - 840dp | 网格列数增加 |
| 小平板 | 840dp - 1200dp | 可考虑双列布局 |
| 大平板 | >= 1200dp | 可考虑类似桌面端的分栏布局（Sidebar + 主区域） |

平板适配优先级低，M7 后根据用户反馈决定是否实施。
