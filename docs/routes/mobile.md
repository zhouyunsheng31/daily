# 移动端路线（Android 沉浸式客户端）· 执行规范

> 版本：v2（2026-08-21 用户拍板精简定稿）
> 定位：本文是**移动端路线的最高执行规范**。与 `docs/routes/README.md`（双路线总纲）和根 `AGENT.md` 一致。

---

## 1. 核心定位与设计哲学

- **与 Web 端纯双端同构**：移动端直接消费 Web 端的 HTML 对话页与系统 App 模板（纯 WebView 容器，沉浸全屏，无 Compose 原生对话页分裂）。
- **移动端核心价值**：**本地持久化存储 + 离线壳 + 高性能沉浸体验**（去浏览器顶底栏、纯手势交互、冷启动极快）。
- **AI 对话**：由服务端标准模型统一提供（保证一致性与稳定性，暂不开放端侧独立接 Key / BYOK）。
- **包与 API 生产**：移动端具备完整的包与 API 生产能力（「文件夹即包」），写好的 API 包直接发布到服务端由受限 vm 执行。
- **系统能力极简**：纯应用内沙箱环境，**彻底废除 Shizuku、无障碍、系统全局悬浮窗等外部系统权限**。
- **技能全部包化**：无独立外挂 skill 目录体系，所有能力/提示词统一装在包内的 `contents.skills` 里（R15/W4 规范）。

---

## 2. 拍板决策清单（D-M 系列）

| # | 决策 | 说明 |
|---|---|---|
| D-M1 | **双端同构消费** | 移动端对话页、桌面、商店、文件管理器全面消费 Web HTML 模板，零原生 UI 分裂 |
| D-M2 | **服务即包（发布到服务端）** | 移动端 AI 可直接创建并发布 API 包到服务端受限 vm 执行，支持跨用户 public 管道 |
| D-M3 | **统一标准模型** | AI 对话走统一标准服务端链路（暂不开放端侧自接 API Key） |
| D-M4 | **彻底摒弃外部特权** | 不依赖、不集成 Shizuku / 无障碍 / 系统级悬浮窗权限 |
| D-M5 | **技能全部包化** | 废弃独立外挂 skills 机制，技能作为包内 `contents.skills` 随包分发 |
| D-M6 | **不开终端/任意进程** | proot 仅在开发调试或内部工具受控环境使用，不对外开放终端 UI 或任意进程 |
| D-M7 | **文件与数据同步** | 本地优先缓存 + 增量对接 Web 端 File Service（files 表 + manifest/blob 端点） |
| D-M8 | **极致性能预算** | 基座 APK < 30MB、冷启动 < 1s、页面滑动稳 60/120fps |

## 3. 里程碑规划（M 系列）

- **M1（同构沉浸壳 + 模板加载）**：
  - M1-1：全屏沉浸式 WebView 容器（edge-to-edge、系统手势返回、无应用感顶底栏）；
  - M1-2：加载 Web 端的系统模板（对话页、桌面、商店），打通 JSBridge 桥接（`apps.list/open`、`storage.*`）；
  - M1-3：本地包缓存与持久化（IndexedDB / 本地文件落盘）；
  - M1-4：文件服务与同步（对接服务端 `/webos/api/files/*`）；
  - M1-5：性能达标（冷启动优化、WebView 预热池 ≤ 2）。
- **M2（包市场消费与 API 生产）**：
  - M2-1：统一包市场浏览、搜索与安装（依赖闭包）；
  - M2-2：移动端 AI 文件夹建包并发布到服务端；
  - M2-3：账号登录与多端数据自动同步。
