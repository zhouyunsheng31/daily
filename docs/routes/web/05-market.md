# 05 · 统一包市场（web 路线）——万物皆可包（R14）

> 现状：商店已有雏形（`webosStoreV1.ts` 模板 + `webos_store_*` 表 + 发布/安装/分享/下载奖励）。本文把它升级为**统一包市场**形态——app/api/skill/theme/bundle… 全在同一市场里按 type 浏览/安装/升级，**不设独立「API 市场」**（R14，2026-08-21 拍板），API 只是包的诸多类型之一。

## 1. 现状盘点（实证）

- 商店形态 = 版本化 HTML App（`system.store`，AI 可改形态）；数据走独立表（发布/安装/下载计数/下载奖励积分）。
- 分享：单 App 轻量分享（`/daily/exp/ap-*`）+ 整套系统分享（`/daily/exp/sh-*`）。
- 技能市场：系统级 skill 分发到用户工作区（已有）。
- 缺口：无 type 维度（只有 app）；无 api 包（端点清单/数据范围声明）；无依赖闭包安装；无审核门槛。

## 2. 升级方案

### 2.1 类型维度与详情页

- 列表/详情/安装端点加 `type` 过滤（app/api/theme/skill/bundle…）。
- **参与门槛（R13，2026-08-21 拍板）**：public 管道（发布/安装/调用/寻址）仅面向注册用户，**游客不参与本 API 互通体系**——api 包创建需登录；不做游客寻址。
- **api 包详情页**：展示端点清单（名称/方法/参数/描述）、数据范围声明（storage 读写前缀 + publishes 命名空间）、network.domains、secrets 需求、调用价目（06 kind='api'）。
- 安装确认页：列明"该包将可使用的能力/数据范围"；敏感能力二次确认（防骗授权，宿主渲染）。

### 2.2 依赖闭包

- 安装时服务端解析 `dependencies` 闭包（含 api 包），一并安装并在清单记录；缺失依赖给出人话提示。
- 版本兼容：`range` 语义化匹配；不满足时阻断并说明。

### 2.3 发布与审核（public 管道配套）

| 环节 | 规则 |
|---|---|
| 发布 | `storePublish` 扩展 type/api 元数据；api 包必须携带 api.json + handlers + 声明 |
| 审核 | 首期站长人工审核 + 自动静态扫描（危险模式/白名单/配额/secret 明文检测） |
| 上架 | 详情页 + 价目；下载奖励积分沿用现有机制 |
| 撤回/下架 | 作者可撤回；站长可下架（审计可查） |
| 更新 | 包新版本 → 市场版本指针更新；已装用户可选升级（权限差异提示） |

### 2.4 AI 找包

- pi 工具 `search_packages` / `install_package`：AI 可搜市场并按用户确认安装；安装行为计审计；付费包必须用户手动确认（不伪造扣款）。

## 3. 计费与审计（接 06）

- **API 调用计费**：调用方付固定微价/次（kind='api'）；幂等键防重复扣费；目录价公示（bootstrap.billing.catalog）。
- **发布者分成**：后置（社区运营阶段再定）；首期为 0。
- **审计**：发布/安装/调用/撤回全链 trace（管理端）；滥用防护（限频/配额/域名白名单/secret 脱敏）。

## 4. 移动端关系

移动端市场 = 消费端（浏览/搜索/安装，含 api 包与依赖闭包）；发布/审核/上架只在 web 做（routes/mobile.md D-M7）。商店 HTML 模板升级在 web 主场开发（R7），移动端 WebView 自动消费。

## 5. 验收用例

- api 包发布 → 详情页端点清单/数据范围正确 → 另一用户安装（确认页列明数据范围）→ 调用成功 → 计费/审计落库。
- 带依赖的 App 安装 → 依赖闭包自动装全；缺依赖时人话提示。
- 静态扫描拦截：含明文 secret/越域域名/超配额的包无法上架（返回人话原因）。
- AI 找包：对话里"找个汇率 API" → AI 搜到并推荐 → 用户确认 → 安装成功，对话中即可用。
