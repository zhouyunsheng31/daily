# 08 · UI（web 路线：信息架构 + 桌面模板 V2 + UI 红线）

> UI 红线（W9）：**正式 UI 设计由用户主导**——AI 只能按用户指示执行（用户给方向 → AI 出候选 → 用户选定 → AI 落地），禁止 AI 自行拍板界面风格/配色/布局。本文只锁定信息架构与工程边界，不定视觉风格。

## 1. 现状信息架构（实证）

- 视图路由：`ScreenView = assistant | desktop | files | profile | app | store | experience`。
- 系统内置 App：`daily.ai / system.desktop / system.store / system.files / system.trash`（desktop/store/trash = 版本化 HTML App，AI 可改形态）。
- 导航：对话页 ⇄ 桌面横滑（`useSwipeNavigation`，已有）；App 全屏运行；登录居中弹窗；个人中心承载账户/用量/套餐/隐私。

## 2. 桌面模板 V2（web 主场开发，移动端自动消费 R7）

把 `server/src/webosDesktopV1.ts` 升级为 V2（保留 V1 可回滚），能力对齐 D18 启动器方向：

1. **多页**：布局数据模型 `pages: [[item…], …]`，图标满页溢出下一页；页指示点跟随。
2. **边缘翻页**：编辑模式拖图标到屏幕边缘（驻留 ~600ms）→ 自动翻页落位。
3. **文件夹**：拖图标叠放（重叠中心距 < 阈值）→ 合并创建 folder（宫格预览 + 打开小窗）；拖出解散。
4. **布局端点**：`GET/PUT /webos/api/desktop-layout`（`server/src/webos/desktopLayout.ts`；存 state，同 appStorage 模式）；**移动端 M1-4 消费同一端点与模板**。

执行纪律：模板类改动部署后必须跑重置脚本 + vm 校验无 SyntaxError（根 AGENT.md Playwright 手册沉淀）；真实账号回归。

## 3. 生成体验补强（对标 Puter builder，调研文档 §2.4）

- **实时预览**：对话内生成 App 时右侧/下方实时预览（iframe 沙箱内跑真实 App）。
- **自检循环**：生成后重载预览、捕获运行时错误 → 回喂 AI 修复 → 再验证（一轮不跑到干净不算完）。
- **逐轮快照**：每次修改 = 快照 + 改动描述；回滚前存安全快照（可撤销的撤销）。
- 点选编辑（element picker）与纯样式滑块为后续增强项。

## 4. UI 的包化边界（安全 UI 例外）

- **安全 UI 例外（不可改，宿主 React 写死）**：权限弹窗/授权页（防骗授权）。
- **其余 UI 可包化**（W4 起）：桌面/商店/文件等系统 App 模板 = 版本化 HTML App（AI 可改）；shell-web 的 design tokens 经 theme 包校验应用（失败回退默认）。
- AI 改 UI 全程版本化可回滚；默认模板常驻可回退。

## 5. 移动端关系

- 桌面/商店模板：web 开发 → 移动端 WebView 消费同一模板（R7）；手势让渡（桌面最左页继续右拉 → 宿主接管露出对话页）属移动端宿主层工作（routes/mobile.md D-M5）。
- 移动端 UI（Compose 壳）按 docs/android/10 执行；本文件只约束 web PWA。

## 6. 验收

- 桌面模板 V2 在 PWA 与 Android WebView 行为一致（多页/文件夹/边缘翻页；布局持久化杀进程重进不变）。
- 生成体验：对话生成 App 有实时预览；运行时错误可自动修复一轮；版本时间线带改动描述；回滚可用。
- UI 红线走查：正式视觉变更均有用户选定记录；权限弹窗/授权页无法被任何包挂载（尝试被拒且审计可查）。
