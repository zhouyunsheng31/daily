# 01 · web 路线产品定位与用户旅程

> 本文回答：web 路线给谁用、解决什么、用户旅程长什么样、什么不做。

## 1. 定位

**手机形态的 AI-native webOS（PWA）**——已上线 `shadowshub.xyz`：

- **AI 助手即系统主页**：对话是创建一切的入口（"说一句话，桌面就多一个 App"）。
- **一切皆包 + 应用市场**：App/API/主题/技能等版本化、可回滚、可分享；**App API 体系是本路线的差异化核心**（App = UI + 数据 + API）。
- **本地优先 + 云端同步**：游客零门槛进入，登录只为同步/迁移/更多额度。
- 与移动端路线的关系：web 是**主场**（核心功能首发地），移动端是**本地镜像**（端侧 AI + 本地运行）。

用户规模现状：web 端用户少（平台先行打磨）；真正的用户洪峰在移动端发布后（R2）。

## 2. 用户分层（现状，沿用）

| 层 | 定义 | 额度/能力 |
|---|---|---|
| 游客 | 未注册（自动发放身份 + 免费额度） | token 配额 1 万（现状配置）；工作区 200MB |
| 会员 | 邮箱验证码注册/登录 | token 配额 10 万；工作区 512MB；游客资产自动迁移 |
| 套餐 | 月卡/积分包（爱发电兑换码 / zpay，支付状态如实展示） | 按档位；管理端可调 |

## 3. 用户旅程（web 版 J1–J7，与 docs/android/01 对应但按 web 现状改写）

### J1 首次打开 —— 30 秒说上话
启动 → 自动游客身份 → AI 对话页（无登录墙）→ AI 主动打招呼 + 建议卡（"给我做个倒数日"/"看看能干什么"）。登录入口在对话页右上角，不主动弹出。

### J2 能力引导 —— 用到才出现
App 需要能力（如网络/API 调用/文件）→ 权限确认卡（列明数据范围）→ 确认后放行；不首启堆弹窗。web 端无系统权限弹窗（浏览器能力检测替代）；**权限弹窗/授权页 = 安全 UI 例外，宿主 React 写死**（W9）。

### J3 日常对话
流式回复、思考折叠、工具 chip、停止/重试、消息长按（复制/引用/回退重发 rebuild）；断流自动 resume + 后台任务恢复（已有）。模型与思考档独立配置（对话页 composer 旁）。

### J4 AI 创建/修改 App —— 魔法时刻
"给我做个记账 App" → AI 流式 + 工具 chip（建文件夹/写代码）→ 完成卡片「打开」→ 全屏运行（iframe 沙箱）→ 桌面同步出现图标 → "改深色" → 新版本 → 可回滚。**本路线补强**：生成中实时预览 + 运行时自检/修复循环 + 逐轮快照描述（对标 Puter builder，见 `docs/webos-xiaoshouji-research.md` §2.4）。

### J5 桌面与个性化
系统桌面（版本化 HTML App）：图标网格/长按编辑/拖拽换位（已有）；**桌面模板 V2**（多页/边缘翻页/文件夹，08 分篇，移动端自动消费）。AI 可改桌面形态（版本化可回滚）。

### J6 市场与分享
包市场：浏览/搜索/安装（App 与 API 包）；单个 App 分享链接/整套分享（已有）；"AI 帮我找"入口（AI 搜市场推荐安装）。API 包详情页展示端点清单与数据范围声明（04/05）。

### J7 账号、备份与恢复
游客 → 邮箱验证码登录（资产自动迁移，已有）；个人中心：积分/用量/套餐/兑换码（已有）；文件管理器（07）；备份导出/导入（07 一阶段后提供）。

## 4. 明确不做（本路线范围外，防蔓延）

- **终端/任意进程执行**（R5）——App 自动执行只走受限 handler（04）。
- **shared 联机房间**（后置，依赖 06）；WebRTC P2P（后置）。
- **web 端 AI BYOK**（首版平台托管 DeepSeek；R11 记录）。
- **user-pays 计费**（R11 记录）；社区运营（审核团队/分成/内容治理）。
- **公共商店对第三方开发者开放投稿**（技术管道先行 W5，运营后置）。
- 桌面端 Shell、Canvas 迁入（旧无限画布收敛为内置 Canvas App，后续单独评审）。
