## 一、概述

### 1.1 产品定位

**形态**：浏览器 + 无限画布 + AI

**用途**：日常 AI 助手

Living Dashboard 是一款融合浏览器与无限画布的 AI 助手产品。它既是浏览器（上网工具），又是画布（个人数据管理），核心是贯穿两者的 AI 能力。产品包含桌面端（Electron + React + TypeScript）和移动端（Kotlin + Jetpack Compose + WebView），双端共享服务器数据，实现多端互通。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **对称设计** | 浏览器主页与画布主页在布局上对称（搜索框↔AI对话框、Logo↔圆形图标、常用网站↔收藏组件），降低学习成本 |
| **原生优先** | 桌面端用 Electron 原生渲染，移动端用 Kotlin + Compose 原生 UI，保证丝滑体验 |
| **轻量优先** | 移动端复用系统 WebView，包体 < 20MB；桌面端 tree-shaking 图标 |
| **多端互通** | 共享服务器数据库，面板/组件/AI 对话/书签/脚本/收藏组件跨端同步 |

## 二、桌面端布局设计

### 2.1 整体框架布局（App Shell）

**状态**：已实现（Phase 4）

**功能描述**：桌面端的整体框架，由顶部栏（Omnibox + TabBar）、左侧侧边栏（Sidebar）、主区域（根据 mainView.type 切换）、底部浮动工具栏（UnifiedToolbar，仅画布模式）和覆盖层（GlobalQuickInput、SettingsPanel、WidgetSearch）组成。

**ASCII 线框图**：

```
┌──────────────────────────────────────────────────────────────────┐
│ [Omnibox 地址栏]  │ [Tab1📌][Tab2][Tab3][+]                      │  ← app-topbar
├────────┬─────────┴──────────────────────────────────────────────┤
│Sidebar │  主区域（根据 mainView.type 切换）                       │
│        │                                                         │
│[面板1] │  ┌─────────────────────────────────────────────────┐   │
│[面板2] │  │                                                 │   │
│[面板3] │  │        web-tab / canvas-panel                   │   │
│        │  │        browser-home / canvas-home               │   │
│        │  │                                                 │   │
│        │  └─────────────────────────────────────────────────┘   │
│        │                                                         │
│[+新建] │  ┌─────────────────────────────────────────────────┐   │
│        │  │ UnifiedToolbar（仅 canvas-panel/canvas-home）    │   │  ← 浮动底部
│        │  └─────────────────────────────────────────────────┘   │
└────────┴─────────────────────────────────────────────────────────┘

覆盖层（z-index 最高）：
  ┌──────────────────────────────────────┐
  │ GlobalQuickInput（左 Alt 唤起）       │
  └──────────────────────────────────────┘
  ┌──────────────────────────────────────┐
  │ SettingsPanel（右侧抽屉）             │
  └──────────────────────────────────────┘
  ┌──────────────────────────────────────┐
  │ WidgetSearch（Ctrl+F 唤起）          │
  └──────────────────────────────────────┘
```

**组件层级**：

```
App
├── app-topbar
│   ├── Omnibox
│   └── TabBar
├── app-body
│   ├── Sidebar
│   └── app-main
│       ├── WebTabFullscreen（mainView.type === 'web-tab'）
│       ├── Workspace（mainView.type === 'canvas-panel'）
│       ├── BrowserHome（mainView.type === 'browser-home'）
│       ├── CanvasHome（mainView.type === 'canvas-home'）
│       ├── UnifiedToolbar（仅画布模式）
│       ├── GlobalQuickInput
│       ├── SettingsPanel
│       └── WidgetSearch
```

**交互行为**：

| 用户操作 | 系统响应 |
|---------|---------|
| 点击 TabBar 中的网页标签 | mainView.type = 'web-tab'，主区域显示该网页 |
| 点击 Sidebar 中的画布面板 | mainView.type = 'canvas-panel'，主区域显示该画布 |
| TabBar 点击 + 按钮 | 新建空白网页标签，mainView.type = 'browser-home' |
| Sidebar 点击 + 按钮 | 新建画布面板，mainView.type = 'canvas-home' |
| Ctrl+L | 聚焦 Omnibox |
| 左 Alt | 唤起 GlobalQuickInput |
| Ctrl+F | 唤起 WidgetSearch |
| 窗口缩放 | 侧边栏折叠/展开，主区域自适应 |

**响应式规则**：

| 窗口宽度 | 行为 |
|---------|------|
| >= 1200px | Sidebar 展开（默认 240px），主区域占满剩余空间 |
| 800px - 1200px | Sidebar 可手动折叠，折叠后仅显示图标条（48px） |
| < 800px | Sidebar 自动折叠为图标条，主区域占满 |

**与移动端的对应关系**：桌面端 App Shell 对应移动端的 BottomBar 导航框架。桌面端的顶部栏 + 侧边栏功能在移动端被重新组织为底部栏 + 更多菜单。

## 七、响应式策略

### 7.1 桌面端窗口缩放行为

| 窗口宽度 | Sidebar | 主区域 | TabBar | UnifiedToolbar |
|---------|---------|--------|--------|---------------|

|------|------|
| BottomBar | 底部固定，5 按钮等宽 |
| 地址栏 | 顶部固定，URL 输入框占满宽度 |
| 常用网站网格 | 4 列 |
| 标签卡片 | 全宽卡片 |

**横屏**：

| 元素 | 行为 |
|------|------|
| BottomBar | 底部固定，按钮间距增大 |
| 地址栏 | 顶部固定，URL 输入框更宽 |
| 常用网站网格 | 6-8 列 |
| 标签卡片 | 2-3 列网格 |
| 画布 | 更宽的视口，组件排列更宽松 |

### 7.3 平板适配

当前未做平板专项适配。以下是规划方向（M7+）：

| 设备 | 屏幕宽度 | 适配策略 |
|------|---------|---------|
| 手机竖屏 | < 600dp | 当前布局 |
| 手机横屏 | 600dp - 840dp | 网格列数增加 |
| 小平板 | 840dp - 1200dp | 可考虑双列布局 |
| 大平板 | >= 1200dp | 可考虑类似桌面端的分栏布局（Sidebar + 主区域） |

平板适配优先级低，M7 后根据用户反馈决定是否实施。
